# PHASE против других парадигм — и путь к универсальности

PHASE не «ещё одна парадигма в ряду». Это **слой дисциплины под парадигмами**:
он даёт то, чего каждой из них не хватает, и умеет их *вмещать*. Ниже —
честный разбор: слабое место классической парадигмы, что PHASE добавляет,
как парадигма ложится на фазы.

## Слабое место каждой парадигмы → вклад PHASE

| парадигма | слабое место | вклад PHASE | как вмещается |
|---|---|---|---|
| **Императивная / ООП** | мутация необратима и незаметна; `a=b+c` стирает; объект = mutable-мешок | мутация внутри фазы обратима; объект = капсула (состояние + инварианты + методы-ядра) | объект-капсула (L4), методы = обратимые ядра, откат метода = F⁻¹ |
| **Функциональная** | чистота достигается персистентными структурами → аллокации/копии на каждое изменение | обратимость = «чистота в рантайме»: undo без персистентных копий | неизменяемость-через-откат: ссылочная прозрачность сохраняется, копий нет |
| **Актёрная** | нет саг: эффекты сообщений не откатываются; «at-most-once» руками | капсула-сообщение несёт состояние+журнал; эффект = фаза, откат цепочки | актор = фаза + капсула; сага = откат применённых шагов |
| **ECS / тик-игры** | снапшоты для отката; недетерминизм | тик = фаза; реконсиляция без снапшотов | уже реализовано (netcode, ensemble) |
| **Транзакционная память / оптимизм** | конфликт → повтор с начала; валидация до записи | validate-ПОСЛЕ-apply + бесплатный откат | TM = валидатор на границе; повтор = ресим |
| **Event-sourcing / CQRS** | хранить весь поток событий ради replay | replay = детерминированный пересчёт; «журнал» = только решения O(решений) | события = входы-границы; состояния пересчитываются, не хранятся |
| **SQL/реляционная** | WAL/откат транзакций дорог | откат транзакции = обратный прогон в памяти | batch_tx → таблица-фаза (phase-etl) |
| **Агентная / когнитивная** | recovery вручную; шаг упал — состояние кривое | шаг агента = фаза; recovery = rollback к верифицированному | L5: agent-step rollback |

## Универсальность — как это уживается

Утверждение: PHASE — **не замена парадигм, а их общий субстрат**, потому что
у всех общая скрытая потребность: *состояние + мутация + возможность
вернуться/проверить*.

- ООП даёт **инкапсуляцию** → PHASE даёт капсулу с инвариантами (сильнее:
  состояние запечатано hash'ем, переносимо).
- FP даёт **детерминизм/чистоту** → PHASE даёт тот же детерминизм **и**
  откат, без персистентных копий.
- Акторы дают **изоляцию** → фазы изолированы так же; плюс откат эффектов.
- Event-sourcing даёт **историю** → hash-цепочка границ + журнал решений.
- TM даёт **оптимизм** → validate-после-apply с бесплатным откатом.

Одна дисциплина («всё есть фаза») покрывает сильные стороны каждой — и лечит
их общую слабость: **дорогой возврат к прошлому состоянию**.

## Почему это не «очередная парадигма»

Парадигмы программирования отвечают на вопрос «как выражать вычисление?»
(процедурно/функционально/сообщениями/потоками данных). PHASE отвечает на
другой вопрос: **«как устроено время, память и отказ любого вычисления?»**
Поэтому PHASE **над** парадигмами, а не рядом: вы пишете в любимой парадигме,
но на фазовом субстрате — и получаете rollback, детерминизм, аудит,
миграцию бесплатно.

## Куда идём (углубление внутрь и наружу)

Внутрь: SoA wide-ядра (AVX2), память-в-VM как первоклассные таблицы-фазы,
`.vcf`-актор (капсула + реестры + порты как живой процесс), event-loop = фаза.
Наружу: real-проекты целиком в парадигме (phase-etl сделан), agent-step
rollback для когнитивного стека SINT, инструменты «компиляции» обычного кода
в обратимые ядра (synth), обсуждение с другими парадигмами на их территории.

Девиз: **мы не заменяем ваш стиль — мы даём вашему состоянию память о
прошлом и право на ошибку без расплаты.**
