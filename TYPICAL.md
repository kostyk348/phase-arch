# PHASE для типовых задач — как выглядит обычное программирование в парадигме

Не «где воткнуть PHASE в старые программы», а: если бы мы программировали
обычные вещи в новой дисциплине — как бы они выглядели и что бы давали.

## Центральная замена

| классическая форма | фазовая форма | что даёт |
|---|---|---|
| временные массивы + free | выделение в фазе (Arena), rollback-to-mark | отказ/ошибка = O(1)-уборка, ноль per-object free |
| клонировать состояние перед экспериментом | применить → измерить → откатить (F⁻¹) | кандидаты без копий: откат O(шагов) |
| errno/исключения + ручная уборка | валидатор на границе: commit или rollback | fail = un-run, состояние не «полу-сломано» |
| лог/WAL перед мутацией | обратимая мутация + hash-сверка | откат без логов внутри фазы |
| недетерминизм/гонки | тик = фаза, детерминизм, hash-chain | воспроизводимость из коробки |

## Карта типовых задач

| типовая задача | классика | фазовая форма | выигрыш |
|---|---|---|---|
| **ETL/пакетная обработка строк** | применить ко всем, при ошибке — стоп/перезапуск | пачка: apply → инвариант → rollback пачки | каскадные нарушения ловятся после apply (batch_tx: 35.8% abort) |
| **A/B / выбор конфигурации** | копия состояния на кандидата | кандидат применяется к базе, проигравший откатывается | 0 копий, лучший коммитится |
| **Парсинг с ошибками** | частичные объекты чистить вручную | парсим в арену; ошибка → rollback записи O(1) | восстановление без сборщика |
| **Ретраи/saga** | снапшот перед шагом | шаги обратимы; провал → откат всей цепочки | частичного состояния нет |
| **Сериализация/миграция данных** | бэкап + перезапись | F⁻¹ при провале инварианта | откат миграции = обратный прогон |
| **Разбор untrusted-входа** | try/catch + free | парсинг в арену + валидатор на границе | rollback вместо очистки |
| **Игровой/серверный тик** | снапшот мира | тик = фаза + реконсиляция | netcode без снапшотов |
| **Сортировка с undo** | хранить исходник | решение-журнал (O(решений)) | порядок восстановим |
| **Шифрование at-rest** | отдельный decrypt | decrypt = обратный прогон (PC1) | один алгоритм на оба направления |

## Рецепты (мини)

1. **A/B без копий**: `mark` → применить A → метрика → `rollback(mark)` →
   применить B → метрика → коммит лучшего. Цена проигравшего = обратный прогон.
2. **Парсер с восстановлением**: каждая запись = своя `mark` в Arena;
   семантический провал → `rollback(mark записи)` (её объекты исчезают O(1)),
   ошибка логируется, парсинг продолжается со следующей записи.
3. **Saga/ретрай**: шаги = обратимые ядра; провал шага k → reverse шагов k..1
   → база как до цепочки → повтор с другими параметрами. Гарантия: либо все
   шаги, либо ни одного — без отдельного компенсирующего кода.
4. **Проверка после применения**: глобальный инвариант (уникальность,
   консервация, лимиты), видимый только после apply — главный кейс rollback.

## Честные границы (для типовых задач тоже)

- Одиночный объект, живущий дольше фазы и освобождаемый вразнобой → обычный
  аллокатор (двухъярусная память).
- Чистая float-математика → на границе, не внутри фазы.
- Задача «просто посчитать» без отката/валидации → фаза не нужна; PHASE —
  дисциплина для задач с мутацией, ошибками и выбором.
