# PHASE на x86 — универсальная дисциплина и обход болячек

> К PART 2 архитектуры. Цель: **на имеющемся железе** (x86-64, Artix)
> преодолеть *софтом решаемые* болячки фон Неймана, честно отделив те, что
> требуют железа. И — симметрично — **обойти болячки самой PHASE**, чтобы
> она не стала новой догмой.

PHASE не «отменяет» фон Неймана на x86: транзисторы, кэши и спекуляция
остаются. PHASE — **слой дисциплины поверх фон-неймановского ядра**:
виртуальная машина, в которой фаза — единица времени, памяти, отказа и
коммуникации. Универсальность — дисциплины, не железа.

---

## 1. Болячки фон Неймана → лекарства PHASE (что реально лечится на x86)

| # | болячка | механизм | лечится на x86? |
|---|---|---|---|
| N1 | **Время деструктивно**: `a=b+c` стирает `a`; откат = снапшоты/WAL | обратимость: источники целы, `F⁻¹` из текущего состояния | **да** (измерено: откат O(шагов), 0 логов внутри фазы) |
| N2 | **GC-паузы и malloc-холод** | арены: память = пик фазы; GC = bulk-reset границы | **да** (4–20× на phase-нагрузках) |
| N3 | **Снапшоты/CoW/репликация для надёжности** | rollback = обратный прогон; реконсиляция = детерминизм + откат | **да** (netcode-пример) |
| N4 | **Недетерминизм, гонки, воспроизводимость** | тик = фаза; hash-chain границ = аудит; фазы не разделяют состояние | **да** |
| N5 | **Спекулятивное исполнение = класс уязвимостей** | ядра branchless; решения — на границах; нет «спекуляции внутрь фазы» | частично (ниже x86 всё равно спекулирует; смягчаем ветвления) |
| N6 | **Deadlock/«упал — перезапускай»** | fail = un-run: откат фазы, повтор кандидата | **да** |
| N7 | **Миграция/персистентность процессов** | капсулы .eml (L4): состояние + траектория + срезы | да (субстрат mime-os есть) |
| N8 | **Память пассивна, данные таскаются по шине** | SoA-лейны, арены = локальность; несколько лейнов на одно ядро | смягчение (memory wall — железо) |
| N9 | **Поиск вслепую O(2^N)** | ось B: MITM sqrt-фактор там, где есть декомпозиция | да, по задачам |
| N10 | **Программа = текст; состояние = «где-то там»** | капсула несёт состояние+инварианты | да |

**Честно не лечится софтом:** энергия стирания (Ландауэр) — нужен
адиабатический чип; memory wall/пропускная способность шины; физическая
спекуляция CPU; латентность произвольного I/O. Это помечается как «требует
железа», не обещается.

## 2. Болячки самой PHASE → обходы (самокритика, симметрия)

| # | болячка PHASE | обход |
|---|---|---|
| P1 | **Обратимость дороже**: источники не уничтожаются → нужны свежие destination, код «раздувается» регистрами | (a) гибрид: фазы для откатываемого/транзакционного, фон-нейман hot-path для чистой арифметики без отката — PHASE слой, не замена; (b) SoA-лейны: амортизация на много потоков данных; (c) AOT/JIT ядер в нативный код |
| P2 | **Интерпретатор медленный** (~3.7–16 ns/leaf) | **готово** (phase-vm v0.1.6): AOT ядер в C + cc -O2 → 0.06 ns/leaf fwd, ~95× |
| P3 | **Float необратим** | (a) целые/фиксированная точка для управления (уже так); (b) float-участки = host-функции НА ГРАНИЦЕ с чекпоинтом только этих участков; (c) внутри фазы float запрещён аксиомой |
| P4 | **Долгоживущие/случайные жизни не поддерживаются** (арены) | двухъярусная память: арены для фаз + обычный malloc для глобальных синглтонов/кэшей; PHASE локализует malloc, не запрещает |
| P5 | **Ветвления требуют журнала (это лог)** | журнал O(решений): 8 B на 500k-итераций цикл; журнал = «траектория» → становится фичей L4 (капсула), а не долгом |
| P6 | **Ранние выходы/goto не поддержаны** (только ifnz/wz/rep) | ранний выход = abort фазы (fail=un-run уже первоклассен); структурная дисциплина как у Janus |
| P7 | **Single-thread** (арена/машина) | per-thread фазы; межфазный параллелизм = независимые фазы-воркеры (dataflow); фазы изолированы → нет когерентностного трафика между ними |
| P8 | **I/O необратим и недетерминирован** | I/O только на границах как входные события (возмущения); внутри фазы I/O нет; события логируются в капсулу для replay |
| P9 | **Хэш-аудит на границе = стоимость** | границы редки (тик/транзакция), хэш ~ нс; дешёво, окупается провенансом |
| P10 | **Скалярные u64, нет SIMD/широких слов** | обратимые XOR/ADD покомпонентны → AVX2-лейны: ядро генерируется под вектор (XOR/ADD/ROT побайтово-обратимы); L0 «wide» — измерено (v0.1.6): AVX2 XOR/ROT векторно, корректность assert; автовекторизатор закрывает разрыв (~1.3×) |
| P11 | **PC1 не аудирован** | CA-раунд + тест-векторы + открытая валидация; статус «демонстратор» не снимается до аудита |
| P12 | **Программы должны писаться в фазовом стиле** | компилятор императивного подмножества → обратимые ядра (Janus-путь): дисциплина прячется в тулчейн |
| P13 | **Семантика «капсула» (L4) не реализована** | **готово** (v0.1.6): src/cap.rs .eml-конверт, заголовки=инварианты, верификация без доверия |

Принцип обхода: **PHASE — это граница, а не клетка**. Всё, что не
выигрывает от фазы (float-математика, глобальные кэши, I/O-стоки), живёт
на границах и честно платит там. Внутри фазы — строгая обратимость. Это и
есть «универсальность на нашем железе»: не замена ядра, а дисциплина,
лечащая софтом-решаемые болячки и помечающая железные.

## 3. Что реализовано (карта к коду)

- Оси: rollback O(шагов) → phase-vm (v0.1.x); арена O(1)-rollback → src/alloc;
  decision-журнал → src/ctl; детерминизм+hash → State::hash/chain_step.
- N3/N4 (реконсиляция без снапшотов) → examples/rollback_netcode.rs.
- P2 (AOT ~95×), P13 (капсула .eml), P10 (wide) → v0.1.6; ось B (MITM BFS 1.6×) → examples/mitm_bfs.rs.
